# Часть II. Современные интерактивные элементы

## Глава 5. Popover API: Интерактивные слои без JavaScript


# Почему эта глава актуальна именно в 2026 году

На протяжении почти тридцати лет браузеры не предоставляли встроенного механизма для создания всплывающих интерфейсов.

Практически каждый веб-проект реализовывал собственную систему отображения:

- выпадающих меню;
- контекстных меню;
- тултипов;
- палитр команд;
- всплывающих фильтров;
- панелей пользователя;
- autocomplete.

Во всех случаях разработчики сталкивались с одними и теми же проблемами:

- вычисление координат элемента;
- столкновение с границами окна браузера;
- управление `z-index`;
- обработка кликов вне элемента;
- закрытие по клавише `Escape`;
- позиционирование при прокрутке страницы;
- поддержка мобильных устройств.

Появление Popover API означает, что эта инфраструктура становится частью самой Web Platform.

Браузер начинает предоставлять готовые высокоуровневые механизмы, которые раньше приходилось реализовывать вручную.

Именно поэтому Popover API считается одной из важнейших технологий современного HTML.

В современной веб-разработке создание всплывающих элементов интерфейса — контекстных меню, панелей фильтров, выпадающих списков, тултипов и командных палитр — исторически требовало написания сложного JavaScript-кода. Инженерам приходилось вручную вычислять координаты (`getBoundingClientRect`), отслеживать клики вне элемента для закрытия, управлять индексами наложения (`z-index`) и бороться с обрезанием элементов контейнерами, имеющими `overflow: hidden`.

Достигнув статуса **Baseline** в начале 2025 года, **Popover API** кардинально изменил этот подход. Он предоставляет нативный, декларативный и высокопроизводительный механизм для отображения контента поверх остальной страницы.

## Что изменилось в 2026 году?

Popover API интересен не только как технология создания всплывающих элементов.

Он демонстрирует фундаментальное изменение философии современной Web Platform.

Долгое время браузер предоставлял лишь низкоуровневые примитивы — DOM, CSS и события мыши.

Из этих примитивов разработчики самостоятельно строили сложные пользовательские интерфейсы.

Сегодня ситуация постепенно меняется.

Браузер начинает предоставлять готовые высокоуровневые интерфейсные механизмы:

- `<dialog>`;
- Popover API;
- Declarative Shadow DOM;
- Navigation API;
- View Transition API;
- встроенную валидацию форм;
- Top Layer;
- Anchor Positioning.

Все эти технологии объединяет одна идея:

> **HTML перестаёт быть языком разметки и становится декларативным API пользовательского интерфейса.**

Popover API является одним из самых ярких примеров этой эволюции.

Изучая его, разработчик учится не только создавать всплывающие панели, но и понимать направление развития всей современной Web Platform.

## 5.1. Эволюция всплывающих элементов и философия Popover API

### От кастомных решений к нативной платформе
Раньше для реализации поповеров разработчики использовали сторонние библиотеки (например, Popper.js / Floating UI) или самописные обертки над абсолютно позиционированными `<div>`. Это неизбежно вело к ряду архитектурных проблем:
* **Протекание контекста наложения:** Всплывающий элемент мог оказаться «запертым» внутри родительского блока с фиксированным позиционированием или `overflow: hidden`.
* **Избыточный JavaScript:** Большие объемы клиентского кода тратились на отмену всплытия событий клика и обработку клавиши `Escape`.

### Popover API как Browser Overlay API

Popover — не просто "всплывающее окно".

Он является частью новой системы Overlay.

```
Browser

│

├── Fullscreen

├── Dialog

├── Popover

├── Select Picker

├── Date Picker

└── Top Layer
```

*Все новые UI API используют одну архитектуру.*


### Popover API vs Элемент `<dialog>`
Важно четко разделять назначение `<dialog>` и Popover API:
* **`<dialog>`** предназначен для **модальных** (и редких немодальных) диалогов, требующих фокуса внимания пользователя, блокировки фона (`inert`) и обязательного подтверждения или отмены действия.
* **Popover API** создан для **немодальных** всплывающих интерфейсов. Пользователь может свободно переключаться между поповером и остальным содержимым страницы, кликать по фону и продолжать работу. Поповеры могут сосуществовать друг с другом.

## 5.2. Базовые концепции: `popover`, `popovertarget` и Top Layer


### Почему появился Top Layer

Top Layer появился не ради элемента `<dialog>`.

Он был создан как универсальная инфраструктура отображения элементов поверх обычного содержимого страницы.

Сегодня Top Layer используется сразу несколькими технологиями Web Platform:

- `<dialog>`;
- Popover API;
- Fullscreen API;
- встроенными системными пикерами браузера;
- будущими компонентами платформы.

Это означает, что Popover API является частью гораздо более крупной архитектуры браузера.

Это уже уровень архитектуры браузеров.

### HTML становится языком управления Overlay

Раньше

```
JS

↓

DOM

↓

Popup
```

Теперь

```html
<button

popovertarget="menu">
```

и

```html
<div

popover>
```

То есть HTML становится декларативным Overlay API.



### Работа с Popover API строится на трех ключевых атрибутах:

1. **`popover`**: Глобальный атрибут, превращающий элемент в поповер. Пока поповер закрыт, он скрыт через свойство `display: none`. При открытии браузер автоматически помещает его в **Top Layer** (верхний слой), гарантируя, что элемент окажется поверх абсолютно всех остальных слоев страницы независимо от их `z-index`.
2. **`popovertarget`**: Атрибут, который применяется к элементам `<button>` или `<input type="button">`. В качестве значения он принимает `id` целевого поповера, связывая кнопку и элемент управления на декларативном уровне.
3. **`popovertargetaction`**: Определяет характер взаимодействия при клике на кнопку-триггер:
   * `toggle` (значение по умолчанию): переключает состояние поповера (открыт/закрыт).
   * `show`: только открывает поповер.
   * `hide`: только закрывает поповер.

### Пример декларативной структуры
Ниже приведен пример создания навигационного меню с использованием нативных атрибутов без единой строчки JavaScript:

```html
<!-- Кнопка-триггер управления поповером -->
<button popovertarget="user-menu" popovertargetaction="toggle">
  Профиль пользователя
</button>

<!-- Сам поповер-контейнер -->
<div id="user-menu" popover>
  <ul style="list-style: none; padding: 8px 16px; margin: 0;">
    <li><a href="#profile">Личный кабинет</a></li>
    <li><a href="#settings">Настройки</a></li>
    <hr style="border: none; border-top: 1px solid #e2e8f0; margin: 8px 0;">
    <li><a href="#logout" style="color: #ef4444;">Выйти</a></li>
  </ul>
</div>
```

## 5.3. Три состояния поповера: `auto`, `manual` и `hint`

Атрибут `popover` может принимать три различных значения, определяющих поведение элемента в системе:

### 1. `popover="auto"` (Поведение по умолчанию)
Режим предназначен для стандартных всплывающих меню, селектов и панелей:
* Поддерживает концепцию **Light Dismiss** (легкое закрытие): поповер автоматически закрывается при клике вне его области или при нажатии клавиши `Escape`.
* Реализует паттерн «один активный»: открытие нового `auto`-поповера автоматически закрывает другие открытые в данный момент `auto`-поповеры (если они не являются его дочерними элементами вложенности).

### 2. `popover="manual"`
Режим полного контроля для разработчика:
* **Не имеет легкого закрытия:** клики вне элемента или нажатие `Escape` не приводят к закрытию поповера.
* Не закрывает другие поповеры при открытии и не закрывается ими.
* Управляется исключительно явно — через кнопки с `popovertarget` или программно через JavaScript-методы.
* Идеально подходит для постоянных плавающих панелей, тост-уведомлений (toasts) или модальных тулбаров, которые должны оставаться видимыми до тех пор, пока пользователь не совершит целевое действие.

### 3. `popover="hint"`
Специализированный режим для контекстных подсказок (tooltips):
* Имеет меньший приоритет в иерархии закрытия.
* Поповеры в режиме `hint` закрываются при открытии других `hint`-подсказок или при переключении фокуса, но не вызывают автоматического закрытия `auto`-поповеров.
* Оптимизирован для отображения короткой справочной информации при наведении или фокусировке.

## 5.5. Синергия с CSS Anchor Positioning

Одной из революционных возможностей современной веб-платформы является связка Popover API с **CSS Anchor Positioning** (позиционированием по якорю).

Раньше для привязки всплывающего меню к кнопке триггера требовался JavaScript, вычисляющий клиентские координаты. Теперь браузер делает это декларативно на уровне стилей. При использовании атрибута `popovertarget` браузер автоматически создает **неявную связь (implicit anchor)** между триггером и поповером.

```css
/* Указываем поповеру позиционироваться относительно его якоря */
#user-menu {
  position-area: bottom span-right; /* Расположить снизу по правее */
  position-try-options: flip-block;  /* Автоматически переворачивать вверх при нехватке места */
  margin: 4px 0 0 0;
}
```
Благодаря этому поповер всегда следует за кнопкой-триггером даже во время прокрутки страницы или изменения размеров окна, полностью без использования скриптов позиционирования.

## 5.6. Программное управление, события и стилизация

### JavaScript API
Управлять состоянием поповера программно можно с помощью трех простых методов:
```javascript
const popover = document.getElementById('user-menu');

popover.showPopover();   // Открыть поповер
popover.hidePopover();   // Закрыть поповер
popover.togglePopover(); // Переключить состояние
```

### События жизненного цикла
Платформа предоставляет два события для контроля процесса открытия и закрытия:
* **`beforetoggle`**: Срабатывает непосредственно перед изменением состояния. Это событие **отменяемое** (`cancelable`), что позволяет использовать `event.preventDefault()`, чтобы прервать открытие или закрытие поповера на основе бизнес-логики (например, незаконченной валидации).
* **`toggle`**: Информирует о том, что состояние видимости поповера успешно изменилось. Содержит свойства `event.oldState` ("closed" / "open") и `event.newState` ("open" / "closed").

```javascript
popover.addEventListener('beforetoggle', (event) => {
  if (event.newState === 'open') {
    console.log('Поповер собирается открыться');
  }
});
```

### CSS-стилизация
Для оформления открытых поповеров применяется специальный псевдокласс:
```css
[popover] {
  border: 1px solid #cbd5e1;
  border-radius: 12px;
  padding: 16px;
  box-shadow: 0 10px 25px -5px rgba(0, 0, 0, 0.1);
  background: #ffffff;
  opacity: 0;
  transform: scale(0.95);
  transition: opacity 0.2s, transform 0.2s, overlay 0.2s allow-discrete, display 0.2s allow-discrete;
}

/* Стилизация поповера в открытом состоянии с поддержкой плавных анимаций (Transition discrete) */
[popover]:popover-open {
  opacity: 1;
  transform: scale(1);
}

/* Плавное скрытие при закрытии через allow-discrete */
@starting-style {
  [popover]:popover-open {
    opacity: 0;
    transform: scale(0.95);
  }
}
```



### Popover API и современные фреймворки

### Заключение главы
Popover API перенес логику работы со сложными плавающими интерфейсами с уровня сторонних библиотек на уровень нативного ядра браузера. Декларативные атрибуты, нативный Top Layer, поддержка состояний `auto`/`manual`/`hint` и интеграция с CSS Anchor Positioning делают поповеры мощным инструментом в арсенале современного архитектора фронтенда.
