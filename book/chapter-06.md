# Часть II. Современные интерактивные элементы

## Глава 6. `<details>` и `<summary>`: Нативные аккордеоны и раскрывающиеся блоки

Элемент `<details>` представляет собой нативный виджет раскрытия (_disclosure widget_), который позволяет пользователю по запросу получать дополнительную информацию или элементы управления. Появление этого элемента в стандартах HTML избавило разработчиков от необходимости писать вспомогательные скрипты для управления состоянием «открыто/закрыто», обрабатывать клики по триггерам и управлять доступностью (_ARIA_).

Сегодня `<details>` и его обязательный партнер `<summary>` превратились в мощный декларативный инструмент, поддерживающий продвинутые паттерны интерфейсов, такие как эксклюзивные аккордеоны и плавные CSS-анимации.

---

## 6.1. Архитектура и специфика Disclosure Widget

Согласно спецификации, стандартная структура виджета выглядит следующим образом:

- **`<details>`**: Главный контейнер-обертка, управляющий состоянием видимости внутреннего контента.
- **`<summary>`**: Первый дочерний элемент внутри `<details>`, выполняющий роль интерактивной легенды или заголовка, по которому кликает пользователь.

### Контентная модель и поведение по умолчанию

- Всё содержимое `<details>`, следующее за элементом `<summary>`, считается дополнительной информацией и скрывается от визуального отображения и вспомогательных технологий в закрытом состоянии.
- Если разработчик не указал элемент `<summary>` внутри `<details>`, браузер автоматически создает стандартную текстовую легенду (например, «Details» на английском языке или локализованный аналог), обеспечивая базовую доступность.

---

## 6.2. Практическое применение и сценарии использования

Элементы `<details>` и `<summary>` находят применение в самых разных интерфейсных паттернах:

1. **FAQ (Часто задаваемые вопросы):** Идеальный инструмент для организации списков «Вопрос-Ответ», позволяющий пользователю быстро сканировать страницу и разворачивать только интересующие пункты.
2. **Технические логи и отчёты о прогрессе:** Скрытие громоздких стеков ошибок (`stack trace`), логов сборки или подробных метрик. В `<summary>` выводится краткий статус (например, _«Сборка завершена с 2 предупреждениями»_), а внутри — детальная информация.
3. **Продвинутые формы и фильтры:** Группировка второстепенных параметров фильтрации в интернет-магазинах или панелях управления, чтобы не перегружать пользователя базовым интерфейсом.

## 6.3. Создание эксклюзивного аккордеона без JavaScript

Одной из важнейших возможностей современного HTML является использование атрибута **`name`** у элемента `<details>`. Это позволяет объединять несколько независимых аккордеонов в единую группу.

### Как работает эксклюзивный аккордеон:

Если несколько элементов `<details>` имеют **одинаковое** значение атрибута `name`, браузер автоматически превращает их в эксклюзивную группу (_exclusive accordion_):

- Когда пользователь открывает один элемент из группы, все остальные элементы с тем же `name` автоматически закрываются.
- Раньше для реализации такого поведения требовалось писать циклы на JavaScript с отслеживанием событий и принудительным изменением атрибута `open`. Теперь эта задача полностью решена на уровне нативного ядра браузера.

```html
<!-- Группа эксклюзивного аккордеона -->
<details name="faq-group">
  <summary>Что такое Baseline?</summary>
  <p>Baseline — это стандарт доступности веб-фич во всех основных браузерах.</p>
</details>

<details name="faq-group">
  <summary>Как работает Popover API?</summary>
  <p>Popover API позволяет выводить контент в Top Layer без сложного JS.</p>
</details>

<details name="faq-group">
  <summary>Зачем нужен атрибут name?</summary>
  <p>Он автоматически закрывает соседние детали в группе аккордеонов.</p>
</details>
```

## 6.4. Интерактивность, состояние `open` и экосистема событий

### Логический атрибут `open`

Состояние виджета отражается в разметке и управляется через булев атрибут `open`:

- Присутствие атрибута `open` означает, что контент развернут.
- Отсутствие атрибута скрывает блок.
- Атрибут можно изменять как декларативно в HTML, так и динамически через JavaScript (`element.open = true`).

### Событие `toggle`

При каждом изменении состояния видимости (как через взаимодействия пользователя с интерфейсом, так и программно) на элементе `<details>` срабатывает событие **`toggle`**. Оно не всплывает (_does not bubble_), но позволяет отслеживать открытие/закрытие блоков:

```javascript
const detailsElement = document.querySelector('details');

detailsElement.addEventListener('toggle', (event) => {
  if (detailsElement.open) {
    console.log('Аккордеон был открыт');
  } else {
    console.log('Аккордеон был закрыт');
  }
});
```

### Нативная интеграция с функцией поиска по странице (Find-in-page)

Современные браузеры обладают интеллектуальной интеграцией с поиском по странице (`Ctrl + F` / `Cmd + F`). Если искомая фраза находится внутри скрытого контента элемента `<details>`, браузер автоматически раскрывает этот блок, генерирует событие `toggle` и подсвечивает совпадение, избавляя пользователя от необходимости вручную искать нужный раздел.

## 6.5. Стилизация и плавные анимации

Исторически анимировать `<details>` было сложно, так как высота закрытого состояния равна `0`, а открытого — `auto`. Современный CSS предлагает эффективные инструменты для решения этой задачи.

### Селекторы состояния

Для кастомизации внешнего вида используются стандартные селекторы:

- `details[open]` — применяется к контейнеру в открытом состоянии.
- Псевдокласс **`:open`** (доступный в современных браузерах) позволяет лаконично стилизовать открытый элемент.

### Пример плавной анимации высоты и поворота иконки

```css
details {
  border: 1px solid #e2e8f0;
  border-radius: 8px;
  padding: 12px 16px;
  background: #ffffff;
  transition: background-color 0.2s ease;
}

details[open] {
  background: #f8fafc;
}

summary {
  cursor: pointer;
  font-weight: 600;
  list-style: none; /* Скрываем стандартный маркер списка в некоторых браузерах */
  display: flex;
  align-items: center;
  justify-content: space-between;
}

/* Кастомная иконка стрелки с плавным вращением */
summary::after {
  content: '▼';
  font-size: 0.75rem;
  transition: transform 0.3s ease;
}

details[open] summary::after {
  transform: rotate(-180deg);
}
```

## 6.6. Типичные архитектурные ошибки и ограничения

Спецификация и практический опыт разработки выделяют несколько критических антипаттернов при работе с `<details>`:

1. **Злоупотребление семантикой (Использование не по назначению):**
   - **Запрещено** использовать `<details>` для создания интерактивных вкладок (_Tabs_) или выпадающих меню (_Dropdowns_). Вкладки предполагают иную модель навигации с помощью клавиатуры (стрелки влево/вправо) и логику выбора активной панели. Для меню существует Popover API или `<selectmenu>`. `<details>` предназначен исключительно для вертикальных списков раскрытия.
2. **Сложная иерархия внутри `<summary>`:**
   - Не следует помещать внутрь `<summary>` интерактивные элементы управления (кнопки, ссылки, поля ввода) или сложные блочные структуры (_включая заголовки `<h1>–<h6>`_). Это ломает доступность для программ экранного доступа (_screen readers_). Если группе аккордеонов требуется общий заголовок страницы или секции, его выносят на уровень выше в стандартные теги заголовков (`<h1>`–`<h6>`), а не пытаются встроить внутрь тега `<summary>`.

### Заключение главы

Элемент `<details>` в связке с `<summary>` — яркий пример эволюции декларативного HTML. Переложив управление состоянием, анимациями, поиском по странице и эксклюзивными аккордеонами на плечи браузера, разработчики получили надежный, доступный и производительный инструмент для создания интерфейсов без избыточного JavaScript-кода.
