# Часть VI. Web Components

## Глава 18. HTML Templates и механизм переиспользования

Элементы **`<template>`** и **`<slot>`** являются фундаментальными строительными блоками современной веб-платформы и архитектуры Web Components. Они позволяют разработчикам декларативно описывать структуры разметки, которые остаются инертными до момента активации, обеспечивая эффективное переиспользование кода и глубокую кастомизацию интерфейса.

---

## 18.1. Элемент `<template>` и его инертность

Элемент `<template>` предназначен для хранения статических фрагментов HTML, которые не рендерятся браузером при первоначальной загрузке документа. В структуре DOM сам тег выглядит как пустая оболочка, в то время как его внутреннее содержимое инкапсулировано внутри специализированного объекта `DocumentFragment`, известного как *содержимое шаблона* (`template contents`).

Главная отличительная черта `<template>` — его **абсолютная инертность**:

* **Изоляция в DOM:** Содержимое шаблона не участвует в жизни основного документа и не доступно для обычных поисков через `document.querySelector` до момента активации.
* **Блокировка побочных эффектов:** Скрипты внутри шаблона не исполняются, изображения и сторонние ресурсы не начинают скачиваться, а медиафайлы не воспроизводятся.
* **Безопасная среда:** Браузер обрабатывает содержимое шаблона внутри изолированного «инертного документа» без контекста просмотра, что исключает любые преждевременные сетевые запросы или выполнение кода.

---

## 18.2. Клонирование и эффективное повторное использование

Основное назначение шаблонов — служить высокопроизводительным чертежом (шаблоном проектирования) для динамического создания элементов пользовательского интерфейса. Вместо того чтобы собирать сложные DOM-деревья из строк внутри JavaScript-кода (что грозит уязвимостями типа XSS, снижением читаемости и падением производительности), разработчики объявляют разметку один раз в декларативном HTML и клонируют её по мере необходимости.

Для активации и переноса содержимого шаблона применяются стандартные методы интерфейса DOM:

* **`cloneNode(true)`:** Создает глубокую копию содержимого шаблона вместе со всеми дочерними узлами, после чего готовый фрагмент внедряется в основное дерево DOM или в Shadow DOM.
* **`document.importNode(node, true)`:** Выполняет аналогичную задачу, дополнительно адаптируя узел под контекст целевого документа (актуально при работе с несколькими документами или фреймами).

Этот подход обеспечивает максимальную производительность рендеринга, так как браузер парсит HTML-разметку внутри шаблона всего один раз при загрузке страницы.

## 18.3. Механизм слотов (`<slot>`) в структуре шаблонов

Если тег `<template>` задает неизменяемый каркас компонента, то элемент **`<slot>`** выполняет роль динамического заполнителя (*placeholder*), позволяя внешнему коду внедрять собственную разметку внутрь закрытой структуры. Это создает мост между Light DOM (контентом пользователя) и Shadow DOM (структурой компонента).

* **Именованные слоты:** Использование атрибута `name` позволяет точно распределять входящий пользовательский контент по разным позициям внутри шаблона. Внешние элементы привязываются к слотам с помощью глобального атрибута `slot`.
* **Слот по умолчанию:** Первый встреченный в шаблоне безымянный слот принимает весь контент, для которого не было найдено явного соответствия по имени.
* **Событие `slotchange`:** Браузер автоматически генерирует это событие на элементе `<slot>` при любом изменении состава назначенных ему узлов, позволяя компоненту вовремя реагировать на обновление внешних данных.

## 18.4. Серверный рендеринг (SSR) и Declarative Shadow DOM

Долгое время шаблоны требовали обязательного наличия клиентского JavaScript для своей активации и превращения в живые компоненты. Однако появление концепции **Declarative Shadow DOM (DSD)** радикально изменило сценарии использования тега `<template>`.

Используя атрибут **`shadowrootmode`** (принимающий значения `open` или `closed`) непосредственно у элемента `<template>` внутри компонента, сервер может передать готовую структуру теневого дерева в первичном потоке HTML-ответа:

* **Мгновенный парсинг:** Браузер не оставляет такой шаблон инертным, а сразу распаковывает его, превращая в теневой корень родительского хост-элемента.
* **Польза для SEO и производительности:** Контент внутри компонента становится доступен для немедленной отрисовки (улучшая метрики вроде LCP) и индексации поисковыми роботами без ожидания загрузки и выполнения тяжелых JavaScript-бандлов.

### Заключение главы

HTML Templates (`<template>` и `<slot>`) переводят создание интерфейсов на уровень декларативной инженерии. Объединяя эффективное кэширование разметки, безопасность и поддержку серверного рендеринга через Declarative Shadow DOM, они формируют прочный фундамент для создания масштабируемых веб-компонентов нового поколения.
