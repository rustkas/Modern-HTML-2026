# 💻 Примеры: Документ как модель данных

Теория становится понятной только тогда, когда её можно увидеть в работе.

В этой главе мы рассмотрим, как браузер преобразует HTML-документ в **объектную модель (DOM)** и как эта модель используется различными подсистемами веб-платформы:

- CSS Engine;
- JavaScript Runtime;
- Accessibility Tree;
- поисковыми роботами;
- браузерными API.

Во всех примерах рекомендуется открыть **Developer Tools → Elements**, чтобы наблюдать, как браузер интерпретирует разметку.

---

# 1. HTML → DOM

HTML является обычным текстовым файлом.

После загрузки страницы браузер выполняет синтаксический анализ (**HTML Parsing**) и строит дерево DOM.

## Исходный HTML

```html
<!DOCTYPE html>
<html lang="ru">
  <head>
    <title>Пример DOM</title>
  </head>

  <body>
    Привет, мир!

    <!-- Комментарий -->
  </body>
</html>
```

---

## Построенное дерево DOM

```
Document
│
├── DocumentType
│     html
│
└── html
      │
      ├── head
      │      │
      │      └── title
      │              │
      │              └── "Пример DOM"
      │
      └── body
             │
             ├── Text
             │      "Привет, мир!"
             │
             └── Comment
                    "Комментарий"
```

Обратите внимание:

- браузер создаёт объекты даже для текстовых узлов;
- комментарии также становятся узлами DOM;
- каждый элемент имеет родителя и может иметь потомков.

DOM представляет собой полноценную объектную модель документа, а не просто отображение HTML-файла.

---

# 2. DOM в DevTools

После открытия страницы рекомендуется открыть:

```
F12

↓

Elements
```

или

```
Inspect
```

В панели **Elements** можно увидеть уже не исходный HTML-файл, а дерево DOM, построенное браузером.

Это особенно заметно при ошибках разметки.

Например:

```html
<p></p>

<div>Hello</div>
```

Несмотря на некорректный HTML, браузер автоматически исправит структуру документа.

В DevTools вы увидите уже исправленное дерево DOM.

Именно поэтому говорят:

> HTML является входными данными, а DOM — внутренней моделью документа.

# 3. Семантика против оформления

Одной из самых распространённых ошибок является использование HTML для оформления.

## ❌ Плохой пример

```html
<div style="font-size:32px;font-weight:bold">Новости компании</div>
```

Визуально страница выглядит правильно.

Однако браузер воспринимает данный элемент как обычный контейнер.

Для поисковой системы это:

```
DIV
```

Для программы экранного доступа:

```
Generic container
```

Никакой информации о структуре документа такой элемент не несёт.

---

## ✅ Хороший пример

```html
<h1>Новости компании</h1>
```

Теперь браузер понимает:

- это главный заголовок;
- он участвует в структуре документа;
- его можно использовать при навигации;
- поисковая система воспринимает его как основную тему страницы.

При этом внешний вид можно полностью изменить при помощи CSS.

Например:

```css
h1 {
  font-size: 18px;
  font-weight: normal;
}
```

Семантика останется прежней.

# 4. Нативные элементы против имитации

Рассмотрим кнопку.

## ❌ Имитация

```html
<div onclick="deleteAccount()">Удалить профиль</div>
```

На первый взгляд всё работает.

Но браузер ничего не знает о назначении этого элемента.

Отсутствуют:

- роль;
- клавиатурная навигация;
- состояние;
- взаимодействие со screen reader.

Чтобы приблизить такой элемент к настоящей кнопке, потребуется написать значительно больше кода:

```html
<div role="button" tabindex="0" aria-label="Удалить профиль">
  Удалить профиль
</div>
```

И дополнительно реализовать обработку клавиш:

- Enter
- Space

---

## ✅ Нативная кнопка

```html
<button type="button">Удалить профиль</button>
```

Браузер автоматически предоставляет:

- роль Button;
- поддержку Tab;
- Enter;
- Space;
- правильную работу Screen Reader;
- корректное взаимодействие с формами.

Именно поэтому спецификация HTML рекомендует использовать **нативные элементы прежде, чем создавать собственные компоненты.**

# 5. DOM и Accessibility Tree

На основе HTML браузер строит ещё одну модель документа.

```
HTML

↓

DOM

↓

Accessibility Tree
```

Например:

```html
<button>Сохранить</button>
```

может быть представлен в дереве доступности примерно так:

```
Button

Name:
    "Сохранить"
```

А следующий код:

```html
<div>Сохранить</div>
```

может попасть в дерево как

```
Generic Container
```

или вовсе не стать интерактивным объектом.

Поэтому правильная семантика влияет не только на код, но и на возможность пользоваться сайтом.

# 6. SEO и структурированные данные

Современные поисковые системы анализируют не внешний вид страницы, а её структуру.

Например,

```html
<article>
  <h1>Modern HTML</h1>

  <p>...</p>
</article>
```

говорит поисковому роботу:

- перед нами самостоятельная публикация;
- у неё есть главный заголовок;
- далее располагается содержание.

---

## Пример использования Microdata

```html
<section itemscope itemtype="https://schema.org/Person">
  <h2 itemprop="name">Алексей Петров</h2>

  <p>
    <span itemprop="jobTitle"> Веб-аналитик </span>
  </p>

  <a href="mailto:alex@example.com" itemprop="email"> alex@example.com </a>
</section>
```

В результате браузер видит не просто текст, а объект типа **Person** со свойствами:

- name;
- jobTitle;
- email.

Такой подход используется поисковыми системами для формирования расширенных результатов поиска (Rich Results).

> **Примечание.** В современных проектах для передачи структурированных данных чаще применяется формат **JSON-LD**, однако знание Microdata полезно для понимания того, как HTML может описывать данные непосредственно в разметке.

---

#№ SEO и JSON-LD

Хотя HTML поддерживает встроенные микроданные (**Microdata**) и RDFa, в современных веб-приложениях наиболее распространённым способом передачи структурированных данных является **JSON-LD (JavaScript Object Notation for Linked Data)**.

В отличие от Microdata, JSON-LD не требует добавления специальных атрибутов (`itemscope`, `itemtype`, `itemprop`) непосредственно в HTML-разметку.

Структурированные данные описываются отдельным JSON-документом, который помещается внутрь элемента `<script>`.

```html
<script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "Person",
    "name": "Алексей Петров",
    "jobTitle": "Веб-аналитик",
    "email": "alex@example.com"
  }
</script>
```

Браузер не отображает содержимое этого элемента пользователю.

Однако поисковые системы, различные сервисы и другие программные агенты могут извлечь эти данные и использовать их для построения собственной модели документа.

Например, поисковая система интерпретирует приведённый выше JSON как объект:

```
Person
│
├── name
│      Алексей Петров
│
├── jobTitle
│      Веб-аналитик
│
└── email
       alex@example.com
```

---

## Сравнение Microdata и JSON-LD

| Microdata                                                 | JSON-LD                                            |
| --------------------------------------------------------- | -------------------------------------------------- |
| Данные встраиваются непосредственно в HTML                | Данные располагаются отдельно от HTML              |
| Используются атрибуты `itemscope`, `itemtype`, `itemprop` | Используется обычный JSON                          |
| Связывает структуру документа и структуру данных          | Полностью отделяет данные от представления         |
| Подходит для небольших документов                         | Предпочтителен для крупных сайтов и веб-приложений |
| Более сложен в сопровождении                              | Проще поддерживать и автоматически генерировать    |

---

## Один и тот же объект двумя способами

### Microdata

```html
<section itemscope itemtype="https://schema.org/Person">
  <h2 itemprop="name">Алексей Петров</h2>

  <p>
    <span itemprop="jobTitle"> Веб-аналитик </span>
  </p>
</section>
```

---

### JSON-LD

```html
<script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "Person",
    "name": "Алексей Петров",
    "jobTitle": "Веб-аналитик"
  }
</script>
```

Оба варианта описывают один и тот же объект предметной области, однако делают это разными способами.

---

### Когда использовать JSON-LD

JSON-LD особенно хорошо подходит для описания:

- статей;
- новостей;
- книг;
- организаций;
- персон;
- мероприятий;
- рецептов;
- интернет-магазинов;
- товаров;
- отзывов;
- видеороликов;
- курсов;
- FAQ.

Именно поэтому большинство современных CMS, генераторов статических сайтов и SSR-фреймворков (Angular SSR, Next.js, Astro, Nuxt и другие) генерируют структурированные данные именно в формате JSON-LD.

> **Архитектурное замечание.** JSON-LD хорошо демонстрирует один из фундаментальных принципов современной Web Platform — разделение структуры документа (HTML) и структуры данных (Linked Data). HTML описывает интерфейс для пользователя, тогда как JSON-LD описывает ту же страницу как объект предметной области для поисковых систем, искусственного интеллекта и других программных агентов.

# 7. Семантическая структура документа

Рассмотрим пример статьи.

```html
<main>
  <article>
    <header>
      <h1>Развитие Web Platform</h1>
    </header>

    <section>
      <h2>История DOM</h2>

      <p>...</p>
    </section>

    <section>
      <h2>HTML Living Standard</h2>

      <p>...</p>
    </section>
  </article>
</main>
```

Такой документ имеет понятную структуру:

```
main
│
└── article
      │
      ├── header
      │      │
      │      └── h1
      │
      ├── section
      │      └── h2
      │
      └── section
             └── h2
```

Браузер понимает:

- где расположен основной контент страницы;
- где начинается самостоятельная статья;
- какие разделы входят в неё;
- какие заголовки относятся к каждому разделу.

Это облегчает навигацию как для пользователей, так и для поисковых систем.

---

# 8. HTML как модель данных

Если взглянуть на HTML глазами архитектора программного обеспечения, то можно увидеть, что документ представляет собой обычную иерархическую модель данных.

```
Document
│
├── Metadata
├── Navigation
├── Main Content
├── Sidebar
└── Footer
```

Такую структуру можно представить практически в любом формате:

```
HTML

↓

DOM

↓

JSON

↓

XML

↓

AST
```

Именно поэтому HTML удобно рассматривать не как язык оформления страниц, а как язык описания данных.

CSS отвечает за внешний вид этой модели.

JavaScript управляет её состоянием.

Браузер обеспечивает её выполнение.

---

# Итоги

После выполнения примеров становится очевидно, что HTML — это значительно больше, чем язык разметки.

Он служит фундаментом современной Web Platform:

- браузер преобразует HTML в объектную модель DOM;
- CSS использует эту модель для построения внешнего вида;
- JavaScript взаимодействует с объектами DOM;
- Accessibility Tree обеспечивает доступность интерфейса;
- поисковые системы анализируют семантическую структуру документа;
- современные фреймворки работают поверх HTML, а не вместо него.

Именно поэтому глубокое понимание HTML является необходимой основой для разработки современных веб-приложений независимо от того, используется ли Angular, React, Vue, Svelte или любой другой фреймворк.
