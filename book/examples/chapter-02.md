## 💻 Примеры: Современная семантика

На основе спецификаций HTML Living Standard и руководств по доступности, рассмотрим конкретные примеры применения семантических элементов. Эти примеры демонстрируют, как правильно структурировать документ, чтобы он был понятен как поисковым роботам, так и вспомогательным технологиям.

### 1. Структура типичного документа
Современная разметка использует элементы-ориентиры (Landmarks), чтобы четко обозначить функциональные зоны страницы.

```html
<body>
  <header> <!-- Группа вводных и навигационных средств -->
    <h1>ТехноБлог</h1>
    <nav> <!-- Основной навигационный блок -->
      <ul>
        <li><a href="/">Главная</a></li>
        <li><a href="/articles">Статьи</a></li>
      </ul>
    </nav>
  </header>

  <main> <!-- Доминирующее содержимое документа; только один на страницу -->
    <article> <!-- Независимая композиция, пригодная для синдикации -->
      <header>
        <h2>Эволюция семантики</h2>
        <p>Опубликовано: <time datetime="2026-07-30">30 июля 2026</time></p> <!-- Машиночитаемая дата -->
      </header>
      <p>Текст статьи о преимуществах нативного HTML...</p>
      <footer> <!-- Информация о разделе (авторство, ссылки) -->
        <address> <!-- Контактная информация автора этой статьи -->
          Связаться с <a href="mailto:author@example.com">автором</a>.
        </address>
      </footer>
    </article>
  </main>

  <footer> <!-- Подвал всего документа -->
    <p>&copy; 2026 ТехноБлог</p>
  </footer>
</body>
```

### 2. Статья (`article`) против Секции (`section`)
Выбор между этими элементами зависит от того, может ли контент существовать независимо.

*   **`<article>`**: Идеально подходит для поста в блоге, комментария или виджета. Например, каждый комментарий под статьей должен быть обернут в свой `article`, так как он является самостоятельным высказыванием.
*   **`<section>`**: Используется для тематической группы контента, которая является частью чего-то большего (например, главы книги или разделы вкладки). Секция почти всегда должна иметь заголовок.

**Пример (Главы в статье):**
```html
<article>
  <h1>HTML5 сегодня</h1>
  <section>
    <h2>История</h2>
    <p>Краткий обзор развития...</p>
  </section>
  <section>
    <h2>Новые теги</h2>
    <p>Описание современных элементов...</p>
  </section>
</article>
```

### 3. Дополнительный контент (`aside`)
Элемент `<aside>` предназначен для контента, который лишь косвенно связан с основным текстом. Это могут быть врезки с цитатами, рекламные блоки или боковые панели.

```html
<article>
  <p>Основное повествование о физике черных дыр...</p>
  <aside>
    <h3>Интересный факт</h3>
    <p>Первое изображение тени черной дыры было получено в 2019 году.</p>
  </aside>
</article>
```

### 4. Иллюстрации и подписи (`figure` и `figcaption`)
Элемент `<figure>` объединяет поток данных (изображения, код, диаграммы), на который ссылаются из текста как на единое целое.

```html
<figure>
  <img src="dom-tree.png" alt="Схема дерева узлов DOM">
  <figcaption>Рис. 1 — Визуализация иерархии Document Object Model</figcaption>
</figure>
```

### 5. Использование `<div>` как «последнего средства»
Согласно спецификации, `<div>` не несет никакой семантической нагрузки. Его следует использовать только тогда, когда семантические теги не подходят, например, для создания оберток (wrappers) под стилизацию или JavaScript-логику.

```html
<!-- div используется только для визуального оформления сетки -->
<div class="container flex-layout">
  <section>
    <h2>Наши услуги</h2>
    <p>...</p>
  </section>
  <section>
    <h2>Контакты</h2>
    <p>...</p>
  </section>
</div>
```

### Резюме по семантике
*   **`<header>` и `<footer>`** не создают новых разделов в плане документа.
*   **`<address>`** нельзя использовать для любых почтовых адресов; он предназначен строго для контактов.
*   **`<time>`** требует атрибута `datetime` для корректной обработки дат программами.
*   **Доступность:** Использование нативных тегов вместо `div` с ролями (например, `main` вместо `role="main"`) гарантирует корректную работу скринридеров без лишнего кода.
