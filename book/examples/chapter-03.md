## 💻 Примеры: HTML как API браузера

В этой главе рассматривается, как современные стандарты позволяют реализовывать сложную логику интерфейса декларативно, используя HTML как прямой программный интерфейс к функциям браузера.

### 1. Модальные окна с элементом `<dialog>`

Элемент **`<dialog>`** предоставляет встроенное решение для всплывающих окон, которое самостоятельно управляет доступностью и фокусом.

- **Императивный подход (JS):** Для открытия модального окна используется метод `showModal()`, который автоматически делает остальную часть страницы **инертной** (`inert`), блокируя взаимодействие с ней.
- **Декларативное закрытие:** Внутри диалога можно использовать форму с атрибутом **`method="dialog"`**, которая закрывает окно без написания JavaScript при нажатии на кнопку отправки.

```html
<!-- Модальное окно -->
<dialog id="myDialog">
  <p>Это нативное модальное окно.</p>
  <form method="dialog">
    <button>Закрыть</button>
  </form>
</dialog>

<!-- Кнопка открытия (требует вызова метода) -->
<button onclick="myDialog.showModal()">Открыть диалог</button>
```

_Примечание: Псевдоэлемент **`::backdrop`** позволяет стилизовать фон (затемнение, размытие) за открытым модальным окном._

### 2. Всплывающие элементы через Popover API

**Popover API** (Baseline 2025) позволяет создавать подсказки, меню и уведомления полностью декларативно.

- **Декларативная связь:** Атрибут **`popovertarget`** на кнопке связывает её с `id` элемента-поповера, избавляя от необходимости писать обработчики событий.
- **Автоматическое поведение:** По умолчанию используется состояние **`popover="auto"`**, которое поддерживает «легкое закрытие» (light dismiss) — окно закроется при клике вне его области или нажатии клавиши Esc.

```html
<button popovertarget="my-popover">Показать меню</button>

<div id="my-popover" popover>
  <p>Это всплывающее меню без единой строки JavaScript!</p>
</div>
```

### 3. Декларативный Shadow DOM (DSD)

DSD позволяет инкапсулировать структуру и стили компонента непосредственно в HTML-разметке, что критически важно для производительности и серверного рендеринга (SSR).

- **Механизм:** Использование элемента `<template>` с атрибутом **`shadowrootmode="open"`** сообщает браузеру, что содержимое шаблона нужно немедленно превратить в теневой корень (shadow root) родительского элемента при парсинге.

```html
<div id="host-element">
  <template shadowrootmode="open">
    <style>
      p {
        color: blue;
        font-weight: bold;
      } /* Стили изолированы внутри компонента */
    </style>
    <p>Я нахожусь в Shadow DOM!</p>
  </template>
</div>
```

### 4. Управление загрузкой через нативные атрибуты

Современный HTML позволяет разработчику напрямую влиять на сетевые приоритеты и алгоритмы отрисовки браузера.

- **Fetch Priority:** Атрибут **`fetchpriority="high"`** указывает браузеру, что данный ресурс (например, изображение первого экрана) является критически важным и должен быть загружен в первую очередь.
- **Lazy Loading:** Атрибут **`loading="lazy"`** откладывает загрузку изображений или фреймов до тех пор, пока пользователь не прокрутит страницу к ним.

```html
<!-- Критически важное изображение (высокий приоритет) -->
<img src="hero-banner.jpg" fetchpriority="high" alt="Главный баннер" />

<!-- Второстепенное изображение (ленивая загрузка) -->
<img src="extra-content.jpg" loading="lazy" alt="Дополнительный контент" />
```

Эти примеры демонстрируют эволюцию HTML от простого языка разметки к мощному **декларативному интерфейсу браузера**, где сложные системные задачи решаются нативными средствами платформы.
