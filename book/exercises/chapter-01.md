## 🧪 Практика: Документ как модель данных

На основе изученных стандартов DOM и HTML, перейдем к практическому применению концепции документа как структурированной модели данных. Эти упражнения помогут вам научиться видеть за визуальным интерфейсом иерархическое дерево узлов и семантическую логику.

### 1. Исследование дерева узлов (Node Tree)

Любая разметка на входе превращается в дерево узлов на выходе. Важно понимать, что в DOM попадают не только теги, но и текстовые фрагменты, и комментарии.

**Задание:**

1. Откройте любой веб-сайт и через инструменты разработчика (F12 -> Console) выполните команду:
   ```javascript
   console.dir(document.documentElement);
   ```
2. Найдите свойство `childNodes`. Обратите внимание на наличие узлов типа `Text` между элементами — это пустые пространства и переносы строк из исходного кода.
3. Сравните `childNodes` (все узлы) и `children` (только узлы-элементы).

**Почему это важно:** Работа с DOM — это манипуляция данными. Понимание разницы между `Node` (абстрактный интерфейс) и `Element` (конкретный тег) — ключ к эффективному использованию Web API.

### 2. Исправление «диво-супа» (Семантика против оформления)

Использование HTML только для оформления (например, `<div>` для всего подряд) лишает документ смысла и затрудняет его обработку программами.

**Задание:** Преобразуйте фрагмент кода, заменив оформительскую разметку на семантическую.

_Было (плохо):_

```html
<div class="header">Заголовок сайта</div>
<div class="nav">
  <div class="link">Главная</div>
</div>
<div class="main-text">
  <div class="title">Статья о DOM</div>
  <div class="content">Текст статьи...</div>
</div>
```

_Стало (правильно):_

```html
<header><h1>Заголовок сайта</h1></header>
<nav>
  <ul>
    <li><a href="/">Главная</a></li>
  </ul>
</nav>
<main>
  <article>
    <h2>Статья о DOM</h2>
    <p>Текст статьи...</p>
  </article>
</main>
```

**Результат:** Теперь документ имеет четкую структуру: поисковые роботы понимают, где главная тема (`<main>`), а вспомогательные технологии могут перемещаться по ориентирам (Landmarks).

### 3. Нативная доступность против имитации

Стандарт WAI-ARIA четко заявляет: лучше использовать нативный элемент HTML, чем имитировать его роль на `div` с помощью стилей и скриптов.

**Задание:** Сравните доступность кнопки.

- **Вариант А:** `<div class="btn" onclick="doSomething()">Нажми меня</div>`
- **Вариант Б:** `<button onclick="doSomething()">Нажми меня</button>`

**Проверка:**

1. Попробуйте сфокусироваться на «кнопке» из Варианта А с помощью клавиши `Tab`. Она будет проигнорирована, так как `div` не является интерактивным элементом по умолчанию.
2. Вариант Б (`<button>`) автоматически доступен с клавиатуры, имеет правильную роль в дереве доступности и поддерживает стандартные события.

### 4. Структурированные данные для SEO (Microdata)

Микроданные позволяют встраивать машиночитаемые аннотации прямо в HTML, превращая текст в понятную для поисковиков модель данных.

**Задание:** Добавьте микроразметку для описания автора статьи, используя атрибуты `itemscope` и `itemprop`.

```html
<section itemscope itemtype="http://schema.org/Person">
  <h2 itemprop="name">Иван Иванов</h2>
  <p itemprop="jobTitle">Фронтенд-разработчик</p>
  <a href="mailto:ivan@example.com" itemprop="email">ivan@example.com</a>
</section>
```

**Результат:** Поисковая система теперь не просто видит текст «Иван Иванов», а понимает, что это объект типа «Человек» с определенным именем и контактами.


### 5. Структурированные данные для SEO (JSON-LD)

На основе концепции HTML как **модели данных** и механизмов создания **машиночитаемых аннотаций**, описанных в стандартах, подготовил задание по внедрению структурированных данных в формате JSON-LD.

---

**Задание:** Разметка «Профиля автора» с использованием JSON-LD

**Цель:** Научиться встраивать в HTML-документ метаданные, которые преобразуют текстовую информацию в структурированные объекты, понятные поисковым роботам и другим автоматизированным системам.

#### Контекст
В Главе 1 мы рассматривали документ как дерево узлов и модель данных. В то время как **Microdata** внедряется непосредственно в атрибуты элементов (`itemscope`, `itemprop`), формат **JSON-LD** использует элемент `<script>` как «блок данных» (data block), который не отображается пользователю, но обрабатывается поисковыми системами.

#### Требования к выполнению:
1.  **Создание блока данных:**
    *   Добавьте в секцию `<head>` или в конец `<body>` элемент `<script>`.
    *   Установите для него атрибут `type="application/ld+json"`.
2.  **Формирование объекта:**
    *   Внутри скрипта создайте JSON-объект, описывающий человека (тип `Person` согласно словарю Schema.org).
    *   Обязательно укажите ключи `@context` (значение `https://schema.org`) и `@type`.
3.  **Заполнение свойств (на основе словаря hCard/Schema.org):**
    *   `name`: Полное имя автора.
    *   `jobTitle`: Должность.
    *   `url`: Ссылка на персональный сайт или профиль в соцсетях.
    *   `sameAs`: Массив ссылок на другие профили автора в сети.
4.  **Связывание с контентом:**
    *   Убедитесь, что данные в JSON-LD соответствуют видимому тексту на странице (принцип консистентности семантики).

#### Практический пример для ориентира:
```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Person",
  "name": "Алексей Петров",
  "jobTitle": "Фронтенд-разработчик",
  "url": "https://example.com/alex",
  "sameAs": [
    "https://github.com/alex-dev",
    "https://linkedin.com/in/alex-petrov"
  ]
}
</script>
```

#### Контрольные вопросы для самопроверки:
1.  **Почему для JSON-LD используется тег `<script>`, а не обычные теги разметки?** (Подсказка: см. раздел о блоках данных, которые не предназначены для рендеринга пользователю).
2.  **В чем преимущество JSON-LD перед Microdata при работе со сложными вложенными структурами?** (Подсказка: изучите, как Microdata требует использования атрибутов `itemref` для связи разрозненных элементов).
3.  **Как поисковая система поймет, что этот блок данных относится именно к текущей странице?** (Подсказка: роль URL документа как базового идентификатора).

---
**Дополнительное задание:**
Попробуйте преобразовать созданный JSON-LD обратно в Microdata, используя атрибуты `itemscope` и `itemprop` на обычных HTML-элементах (например, в блоке `<footer>`), чтобы увидеть, как одна и та же модель данных может быть выражена разными синтаксическими средствами.

---

Эти практики подтверждают: HTML — это не просто визуальный слой, а **фундаментальная модель данных**, на которой строится вся логика взаимодействия в вебе.
