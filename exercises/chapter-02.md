## 🧪 Практика: Современная семантика

На основе спецификаций HTML Living Standard и руководств по доступности (WAI-ARIA), перейдем к практическим задачам по внедрению смысловой разметки. Эти упражнения помогут закрепить понимание того, когда использовать специализированные элементы, а когда — нейтральные контейнеры.

### 1. Проектирование ориентиров (Landmarks)
Элементы-ориентиры позволяют пользователям вспомогательных технологий быстро перемещаться по основным зонам страницы.

**Задание:** Создайте структуру главной страницы сайта, используя следующие правила:
*   Используйте **`<header>`** для вводной части страницы и **`<nav>`** для основного блока навигации. Помните, что `<header>` не создает новый раздел в плане документа.
*   Разместите основное содержимое в единственный видимый элемент **`<main>`**. Убедитесь, что он является «иерархически правильным»: его предками могут быть только `html`, `body`, `div`, `form` (без имени) или автономные веб-компоненты.
*   Добавьте **`<footer>`** для информации о правах собственности и ссылок на правила конфиденциальности.

### 2. Статьи и вложенные комментарии
Элемент **`<article>`** представляет собой завершенную композицию, которая может существовать независимо от остальной страницы.

**Задание:** Разметьте публикацию в блоге с комментариями:
*   Оберните сам пост в `<article>`.
*   Каждый комментарий пользователя также оберните в отдельный вложенный элемент **`<article>`**, так как комментарий — это тоже независимая единица контента.
*   Внутри каждого комментария используйте **`<footer>`**, чтобы указать автора и дату публикации. Допускается размещение подвала в начале раздела, если это логично для структуры.

### 3. Тематические разделы против контейнеров для стилей
Важно различать смысловые группы контента и технические обертки для дизайна.

**Задание:** Проведите рефакторинг фрагмента кода:
*   Замените `<div>` на **`<section>`**, если содержимое логически связано и должно отображаться в плане (outline) документа. Помните, что раздел обычно требует заголовка (`h1`–`h6`).
*   Используйте **`<div>`** как «элемент последнего средства», если контейнер нужен только для применения CSS (например, `display: flex`) или манипуляций через JavaScript.

### 4. Точные данные: Время и Контакты
Семантика HTML позволяет передавать данные не только людям, но и программам.

**Задание:** Реализуйте разметку контактов автора:
*   Используйте **`<time>`** с атрибутом `datetime` для указания даты публикации (например, `<time datetime="2026-07-30">`). Это делает дату машиночитаемой для поисковых систем.
*   Используйте **`<address>`** строго для контактной информации автора статьи или владельца сайта. 
*   **Внимание:** Не используйте `<address>` для почтовых адресов, если они не являются контактами для связи (для обычных адресов в тексте используйте `<p>`).

### 5. Иллюстрации и код
Элемент **`<figure>`** объединяет контент, который может быть перемещен в другое место документа (например, в приложение) без потери смысла.

**Задание:** Разметьте фрагмент программного кода:
*   Используйте `<figure>` для группировки кода и его описания.
*   Вставьте код внутрь элементов `<pre><code>` для сохранения форматирования и указания типа данных.
*   Добавьте подпись через **`<figcaption>`**. Ссылайтесь на фигуру в тексте по её подписи (например, «см. листинг 1»), а не по относительному положению («см. код ниже»), чтобы сохранить гибкость при изменении дизайна.

Эти практики делают код более надежным, улучшают SEO и обеспечивают нативную доступность без необходимости использования избыточных ARIA-атрибутов.
