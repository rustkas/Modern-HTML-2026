## 🧪 Практика: Элемент `<dialog>`

На основе стандартов HTML Living Standard и руководств по доступности (ARIA), разберем практические сценарии использования элемента `<dialog>`. Эти задания помогут вам освоить нативное управление модальными окнами, которое пришло на смену сложным JavaScript-библиотекам.

### 1. Создание модального окна и эффект «инертности»

Главное отличие модального диалога от обычного — полная блокировка взаимодействия с остальной страницей.

**Задание:**

1. Создайте элемент `<dialog>` с идентификатором и кнопкой закрытия внутри.
2. Реализуйте открытие через JavaScript методом `.showModal()`.
3. Убедитесь, что при открытом окне все остальные элементы страницы стали **инертными** (не кликаются и не выбираются через Tab).
4. Добавьте стилизацию фона через псевдоэлемент **`::backdrop`**, чтобы визуально отделить диалог от заблокированного контента.

**Почему это важно:** Метод `.showModal()` автоматически помещает окно в **Top Layer** (верхний слой), игнорируя любые настройки `z-index` других элементов.

### 2. Сбор данных через `method="dialog"`

Современный HTML позволяет закрывать диалоги и возвращать значения без написания обработчиков событий для каждой кнопки.

**Задание:**

1. Поместите внутрь `<dialog>` форму с атрибутом **`method="dialog"`**.
2. Добавьте две кнопки: `<button value="cancel">Отмена</button>` и `<button value="confirm">ОК</button>`.
3. Напишите скрипт, который слушает событие `close` на диалоге и выводит значение свойства **`returnValue`** в консоль.

**Результат:** При нажатии на любую кнопку форма не отправляется на сервер, а просто закрывает диалог, передавая `value` кнопки в свойство `returnValue` объекта диалога.

### 3. Нативная доступность и управление фокусом

Правильное управление фокусом — критический аспект доступности (A11y).

**Задание:**

1. Добавьте атрибут **`aria-labelledby`**, ссылающийся на заголовок внутри диалога, чтобы скринридеры могли озвучить название окна.
2. Используйте атрибут **`autofocus`** на конкретном элементе управления (например, на первом поле ввода), чтобы фокус переместился туда сразу после открытия.
3. Проверьте, что при нажатии клавиши **Esc** диалог закрывается автоматически (это поведение обеспечивается браузером для `showModal`).
4. Убедитесь, что после закрытия фокус автоматически вернулся на кнопку, которая открывала диалог.

### 4. Реализация «Легкого закрытия» (Light Dismiss)

В последних обновлениях стандарта (2024-2026) появился нативный способ закрытия окна кликом по фону.

**Задание:**

1. Добавьте к элементу `<dialog>` атрибут **`closedby="any"`**.
2. Проверьте работу: теперь окно должно закрываться не только по Esc, но и при клике на `::backdrop` (вне области самого диалога).
3. Сравните это поведение со значением `closedby="none"`, которое запрещает любое автоматическое закрытие пользователем.

### 5. Рефакторинг: Работа над ошибками

Исправьте фрагмент кода, содержащий типичные ошибки использования `<dialog>`.

**Исходный «плохой» код:**

```javascript
const dialog = document.querySelector('dialog');
// Ошибка 1: использование tabindex на самом диалоге
// Ошибка 2: ручное удаление атрибута open для закрытия
function badClose() {
  dialog.removeAttribute('open');
}
```

**Ваше задание:**

- Удалите `tabindex` с элемента `<dialog>`, так как он не предназначен для фокусировки (фокусироваться должно содержимое).
- Замените `removeAttribute('open')` на метод **`.close()`**.

**Почему это критично:** Ручное удаление атрибута `open` скроет окно визуально, но браузер не разблокирует страницу (она останется `inert`), не вернет фокус и не сгенерирует событие `close`.
