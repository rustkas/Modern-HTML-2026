## 🧪 Практика

Современный HTML предоставляет разработчикам мощные инструменты, которые ранее требовали использования сторонних библиотек и сложного JavaScript-кода. Переход к **HTML Living Standard** обеспечил постоянное обновление платформы новыми нативными возможностями. Рассмотрим практические примеры того, как современные стандарты HTML решают задачи фронтенда эффективнее и быстрее.

### 1. Интерактивные элементы без JavaScript
Одной из главных тенденций последних лет стал перенос логики пользовательского интерфейса с JavaScript на нативный HTML.
*   **Модальные окна через `<dialog>`:** Элемент `<dialog>` позволяет создавать модальные окна, которые автоматически управляют фокусом и блокируют остальную часть страницы (делают её **inert**). Для его открытия достаточно метода `showModal()`, а закрытие может осуществляться через встроенный атрибут `closedby` (клавишей Esc или кликом вне окна).
*   **Popover API:** Новый глобальный атрибут **`popover`** (Baseline 2025) позволяет создавать всплывающие подсказки, меню и уведомления. Он работает декларативно: атрибут `popovertarget` на кнопке связывает её с целевым элементом без написания обработчиков событий на JavaScript.
*   **Раскрывающиеся списки через `<details>`:** Элемент `<details>` в сочетании с `<summary>` создает раскрывающиеся виджеты (аккордеоны). Начиная с последних версий стандарта, атрибут `name` позволяет группировать несколько `<details>`, создавая эксклюзивные аккордеоны, где открытие одной секции автоматически закрывает остальные.

### 2. Веб-компоненты и инкапсуляция
**Web Components** позволяют создавать собственные повторно используемые теги, не опасаясь конфликтов стилей или скриптов.
*   **Shadow DOM:** С помощью метода `attachShadow()` разработчик создает изолированное дерево DOM. Стили внутри него не «протекают» наружу, а внешние стили страницы не влияют на внутренние элементы компонента.
*   **Декларативный Shadow DOM:** Использование элемента `<template>` с атрибутом **`shadowrootmode="open"`** позволяет определять структуру теневого DOM прямо в разметке HTML. Это критически важно для серверного рендеринга (SSR), так как позволяет браузеру отобразить компонент до загрузки JavaScript.
*   **Слоты (`<slot>`):** Элемент `<slot>` служит заполнителем в веб-компоненте, куда можно передать любой пользовательский контент из основного документа.

### 3. Оптимизация производительности на уровне атрибутов
HTML взял на себя функции управления загрузкой ресурсов, которые раньше возлагались на скрипты оптимизации.
*   **Ленивая загрузка (`loading="lazy"`):** Атрибут `loading` для тегов `<img>` и `<iframe>` позволяет браузеру откладывать загрузку ресурсов до тех пор, пока они не окажутся рядом с областью видимости пользователя.
*   **Приоритеты ресурсов (`fetchpriority`):** Разработчики могут явно указать важность ресурса для браузера. Например, `fetchpriority="high"` на критическом изображении (LCP) ускоряет отрисовку первого экрана.
*   **Подсказки ресурсов (`rel="preload"`):** Через тег `<link>` можно заранее уведомить браузер о необходимости загрузить шрифты или стили, которые понадобятся позже.

### 4. Нативная доступность (Accessibility)
Важнейшее правило современного веба: **использовать нативные элементы вместо ARIA**, если такая возможность существует. Нативные теги, такие как `<button>`, `<h1>` или `<nav>`, уже содержат в себе всю необходимую семантику и встроенную поддержку навигации с клавиатуры. 
*   **Управление фокусом:** Современный HTML позволяет точно настраивать порядок обхода элементов через `tabindex` и автоматически переносить фокус на нужные поля при загрузке страницы через атрибут `autofocus`.
*   **Валидация форм:** Встроенная проверка типов (`type="email"`, `type="url"`) и атрибуты `required`, `pattern` обеспечивают базовую безопасность и удобство заполнения форм без участия JavaScript.

Использование этих практик делает код более надежным, легким для поддержки и быстрым для пользователя, подтверждая, что **HTML остается фундаментом современной Web-платформы**.

Для закрепления материала по современному HTML и веб-платформе, вот серия практических заданий, основанных на актуальных стандартах и спецификациях.

### 1. Работа с элементом `<dialog>` и формами
**Задание:** Создайте модальное окно для подтверждения действия (например, удаления профиля).
*   Используйте элемент `<dialog>` для создания окна.
*   Реализуйте открытие окна с помощью метода `showModal()`, чтобы заблокировать остальную часть страницы (сделать её `inert`).
*   Внутри диалога создайте форму с `method="dialog"`.
*   Добавьте две кнопки: «Отмена» (с `value="cancel"`) и «Подтвердить» (с `value="confirm"`).
*   **Дополнительно:** Стилизуйте затемнение фона за диалогом, используя псевдоэлемент `::backdrop`.
*   Напишите скрипт, который выводит в консоль результат выбора пользователя, используя свойство `returnValue`.

### 2. Реализация декларативного интерфейса с Popover API
**Задание:** Создайте всплывающее меню навигации без использования JavaScript для логики открытия/закрытия.
*   Создайте элемент (например, `<div>` или `<ul>`) с глобальным атрибутом `popover`.
*   Используйте кнопку (`<button>`) с атрибутом `popovertarget`, значение которого совпадает с `id` вашего поповера.
*   Настройте автоматическое закрытие при клике вне области («light dismiss»), установив значение атрибута `popover="auto"` (это значение по умолчанию).
*   **Сравнение:** Напишите краткое пояснение, в каких случаях для этого интерфейса лучше подошел бы `<dialog>`, а в каких — Popover API.

### 3. Создание инкапсулированного веб-компонента
**Задание:** Разработайте кастомный элемент `<user-card>`, который отображает информацию о пользователе.
*   Создайте класс, наследуемый от `HTMLElement`, и зарегистрируйте его через `customElements.define()`.
*   Используйте Shadow DOM (`attachShadow({mode: 'open'})`) для изоляции стилей компонента от основной страницы.
*   Примените элемент `<template>` для определения структуры карточки и элемент `<slot>` для передачи имени пользователя из основного документа.
*   Добавьте стили внутри Shadow DOM (через тег `<style>` в шаблоне) и убедитесь, что они не влияют на внешние элементы страницы.

### 4. Оптимизация производительности и приоритетов загрузки
**Задание:** Настройте страницу с большим количеством медиа-контента для максимально быстрой отрисовки.
*   Добавьте атрибут `loading="lazy"` для всех изображений, находящихся вне первого экрана.
*   Для главного изображения (LCP — Largest Contentful Paint) установите атрибут `fetchpriority="high"`, чтобы ускорить его загрузку.
*   Используйте `<link rel="preload">` в секции `<head>` для предварительной загрузки критического шрифта или важного скрипта.
*   Реализуйте адаптивные изображения с помощью тега `<picture>` и нескольких элементов `<source>` с разными атрибутами `media` и `srcset`.

### 5. Семантика и доступность (Accessibility)
**Задание:** Проведите аудит фрагмента кода и замените ARIA-роли нативными элементами HTML.
*   Замените `<div role="button">` на нативный элемент `<button>`.
*   Вместо использования сложных JS-скриптов для раскрывающихся списков примените элементы `<details>` и `<summary>`.
*   Разметьте основные области страницы (ориентиры), используя семантические теги `<main>`, `<nav>`, `<header>` и `<footer>` вместо `div` с ролями `landmark`.
*   Убедитесь, что все интерактивные элементы доступны с клавиатуры и имеют корректные «доступные имена» (accessible names).

Эти задания помогут понять, как HTML эволюционировал из простого языка разметки в мощную прикладную платформу, способную решать сложные задачи интерфейса и производительности стандартными средствами.
