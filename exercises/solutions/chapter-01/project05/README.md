Дублирование разметки в данном примере носит **учебный** характер, но на практике так делать не нужно. Это сделано исключительно для того, чтобы в одном документе наглядно продемонстрировать два разных синтаксиса решения одной и той же задачи.

В реальной разработке выбирается **только один** подход. Вот почему между ними есть разница:

### 1. JSON-LD (в теге `<script>`)

* **Для кого:** Для поисковых роботов, парсеров и автоматизированных систем.
* **Как работает:** Данные скрыты в отдельном блоке и никак не влияют на визуальное отображение для пользователя.
* **Плюсы:** Не загромождает HTML-код визуальных элементов, легко поддерживается, масштабируется и валидируется. Современный стандарт, который настоятельно рекомендуется Google и Яндекс.

### 2. Microdata (с использованием атрибутов `itemscope`, `itemprop`)

* **Для кого:** И для пользователей (они видят текст), и одновременно для роботов (которые считывают те же HTML-теги благодаря специальным атрибутам).
* **Как работает:** Метаданные «вплетаются» прямо в разметку страницы. Поисковый робот читает те же блоки, которые видит человек в браузере.
* **Минусы:** Усложняет HTML-код, делает его менее гибким, особенно при создании сложных вложенных структур (когда элементы разбросаны по разным частям страницы).

---

### Главный принцип

Поисковые системы ожидают увидеть на странице **единую модель данных**.

Если вы используете **JSON-LD**, дублировать те же данные через Microdata в теле страницы **не нужно**. Достаточно оставить только блок `<script type="application/ld+json">`, а в самом HTML выводить обычный текст для пользователей без каких-либо атрибутов `itemscope`.

Дублирование в рамках одного документа может запутать поискового робота или создать избыточность, хотя современные алгоритмы обычно умеют это обрабатывать. Выбирайте что-то одно — сегодня индустриальным стандартом де-факто является **JSON-LD**.
