# Сравнение: когда использовать `<dialog>`, а когда Popover API

* **Когда лучше использовать Popover API:**
  * Для всплывающих элементов интерфейса, которые **не блокируют** остальную страницу (например, выпадающие меню, подсказки/tooltip, панели уведомлений, селекторы).
  * Когда пользователю нужно иметь возможность взаимодействовать с контентом на странице вне всплывающего окна, не закрывая его принудительно (если используется `popover="manual"`), либо легко закрывать кликом вне области (`popover="auto"`).
  * Когда требуется декларативный подход без написания JavaScript-логики открытия и закрытия.


* **Когда лучше использовать `<dialog>`:**
  * Для модальных окон, требующих **обязательного внимания** пользователя (например, подтверждение удаления аккаунта, критические ошибки, формы авторизации или заполнения данных).
  * Когда нужно заблокировать («сделать inert») остальной контент страницы, чтобы пользователь не мог кликать по фоновым элементам, пока окно открыто (вызывается через метод `showModal()`).

---

Механика работы **Popover API** основана на декларативном подходе (без необходимости писать скрипты на JavaScript для базового открытия и закрытия) и браузерном управлении слоями (Top Layer).

## Принцип работы примера состоит из нескольких ключевых элементов:

### 1. Декларативная связь через атрибуты (`popover` и `popovertarget`)

Главная особенность Popover API — вся логика зашита на уровне HTML:

* **Атрибут `popover="auto"**` на элементе `div` (с `id="navPopover"`) говорит браузеру, что этот элемент является всплывающим окном. Значение `auto` включает режим **«light dismiss»** (лёгкое закрытие): элемент автоматически закроется, если пользователь кликнет за его пределами или нажмет клавишу `Esc`.
* **Атрибут `popovertarget="navPopover"**` на кнопке связывает её с поповером. Браузер автоматически понимает, что при клике на эту кнопку нужно переключить состояние поповера (открыть, если он закрыт, и закрыть, если открыт). Для этого не нужно писать `addEventListener`.

### 2. Помещение в Top Layer (Верхний слой)

Когда поповер открывается, браузер автоматически перемещает его в специальный **Top Layer** (верхний слой страницы).

* Это гарантирует, что элемент окажется поверх абсолютно всех остальных блоков на странице, независимо от их значений `z-index` или ограничений в CSS-дереве (например, если родительский элемент имеет `overflow: hidden`).

### 3. Управление фокусом и доступность (Accessibility)

Браузер берёт на себя часть работы по обеспечению доступности:

* При открытии поповера фокус может переходить на него или управляться встроенными механизмами.
* Нажатие клавиши `Esc` корректно закрывает всплывающее меню.

---

### Главные отличия от старого подхода

Раньше для создания такого меню разработчикам приходилось:

1. Вешать обработчик клика (`click`) на кнопку через JavaScript.
2. Менять CSS-свойство `display` (например, с `none` на `block`).
3. Добавлять глобальный слушатель кликов на `document`, чтобы отслеживать клики вне меню и закрывать его (реализовывать «light dismiss» вручную).
4. Следить за `z-index`, чтобы меню не перекрывалось соседними элементами.

Теперь всю эту рутинную работу браузер выполняет нативно и прямо из коробки с помощью Popover API.
