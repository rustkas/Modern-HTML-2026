### Разбор ключевых механизмов оптимизации:

1. **`loading="lazy"` (Отложенная загрузка):**

   Применяется к изображениям и элементам, находящимся ниже первого экрана (в галерее). Браузер не станет скачивать и обрабатывать эти файлы, пока пользователь не прокрутит страницу близко к ним, что значительно сокращает первоначальный объем трафика и ускоряет начальную отрисовку.

2. **`fetchpriority="high"` (Приоритет для LCP):**

   Главный визуальный элемент (`hero-section`) является кандидатом на Largest Contentful Paint (LCP) — важнейшую метрику Core Web Vitals. Атрибут `fetchpriority="high"` в сочетании с тяжелыми графическими фильтрами подсказывает браузеру, что этот ресурс и его рендеринг имеют наивысший приоритет.

3. **Предзагрузка через `<link rel="preconnect">` и Google Fonts:**

   Секция `<head>` содержит оптимизированные подсказки соединений с внешними серверами Google (`preconnect`), что позволяет мгновенно инициировать сетевой запрос к шрифту `Inter` с параметром `display=swap`, исключая задержки текста (FOIT) и ускоряя общую интерактивность.

4. **Адаптивные элементы и GPU-нагрузка через SVG-фильтры:**

   Использование расширенной верстки позволяет гибко управлять отображением контента. Дополнительно задействованы тяжелые SVG-фильтры (`feTurbulence`, `feDisplacementMap`, `feGaussianBlur`), которые имитируют сложную графическую нагрузку на процессор и графический чип (GPU) в реальном времени, позволяя оценить производительность отрисовки интерфейса в DevTools.

5. **Адаптивные изображения `<picture>`:**

   Комбинация тегов `<source>` с атрибутами `media` позволяет браузеру выбирать наиболее подходящий источник контента под конкретное устройство. Даже при использовании SVG-заглушек или адаптивных ресурсов это исключает передачу избыточных данных и оптимизирует сетевой трафик для мобильных пользователей.

6. **Атрибут `defer` в теге `<script>`**

   Атрибут `defer` в теге `<script>` управляет моментом загрузки и выполнения скрипта, чтобы не блокировать отображение страницы:
   - **Параллельная загрузка:** Браузер начинает скачивать файл `script.js` в фоновом режиме одновременно с разбором (парсингом) HTML-кода страницы.
   - **Отложенное выполнение:** Скрипт не выполнится сразу после скачивания. Браузер дождется полного построения дерева DOM (когда весь HTML будет разобран), и только после этого выполнит скрипт — но обязательно **до** срабатывания события `DOMContentLoaded`.
   - **Польза для производительности:** Это предотвращает блокировку рендеринга страницы (Render-blocking JavaScript). Пользователь видит контент быстрее, а скрипт не падает с ошибкой из-за того, что элементы на странице еще не успели создаться.
