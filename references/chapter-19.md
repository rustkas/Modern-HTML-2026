Для **Главы 19**, посвященной интеграции веб-компонентов с современными фреймворками и библиотеками, основными источниками являются разделы спецификаций HTML и DOM, описывающие механизмы регистрации, инкапсуляции и обеспечения совместимости.

Хотя технические спецификации (HTML, DOM) не содержат прямых упоминаний конкретных коммерческих инструментов (таких как React или Vue), они определяют **стандарты взаимодействия**, на которых строится работа этих фреймворков с нативными компонентами.

### Основы взаимодействия и совместимости

Веб-компоненты по определению являются переиспользуемыми элементами с инкапсулированной функциональностью, которые могут быть интегрированы в любое веб-приложение независимо от используемого стека технологий.

- **MDN: Web Components** — общий обзор технологий (Custom Elements, Shadow DOM, Templates), позволяющих создавать компоненты, защищенные от конфликтов кода внутри приложений.
- **MDN: Using shadow DOM** — подробное описание инкапсуляции, которая гарантирует, что стили и скрипты фреймворка не нарушат внутреннюю логику веб-компонента и наоборот.
- **HTML Standard: Section 4.13 Custom elements** — спецификация, позволяющая авторам создавать собственные полноценные DOM-элементы, которые браузер и сторонние инструменты (фреймворки) воспринимают как нативные.

### Межфреймворковое взаимодействие и изоляция

Для обеспечения работы нескольких библиотек на одной странице без конфликтов имен используются специализированные механизмы реестров.

- **HTML Standard: Section 4.13.1.7 Scoped custom element registries** — ключевой раздел для темы сосуществования фреймворков. Описывает использование изолированных реестров для предотвращения конфликтов имен между компонентами из разных библиотек.
- **DOM Standard: CustomElementRegistry** — программный интерфейс для управления регистрацией элементов в глобальном или локальном контексте.

### Интеграция с инфраструктурой (Lit, Stencil, Angular Elements)

Библиотеки для создания веб-компонентов (например, Lit или Stencil) активно используют низкоуровневые API для эмуляции поведения нативных элементов.

- **HTML Standard: Section 4.13.7.1 The ElementInternals interface** — позволяет кастомным компонентам (в том числе созданным через Angular Elements или Stencil) управлять внутренними состояниями, такими как валидация форм и доступность, скрытыми от потребителя.
- **HTML Standard: Section 4.13.7.4 Accessibility semantics** — использование программного задания ролей и состояний ARIA, что критично для корректного взаимодействия компонентов с «деревом доступности» внутри сложных фреймворков.

### Angular Elements

Официальная документация Angular предоставляет исчерпывающее руководство по пакету `@angular/elements`.

- **[Angular Elements Overview](https://angular.dev/guide/elements)** — подробное руководство, объясняющее, как превратить Angular-компонент в пользовательский элемент (Custom Element) с помощью API `createCustomElement()`. Здесь описаны маппинг входных свойств (Input) в HTML-атрибуты и выходных событий (Output) в пользовательские события (Custom Events).
- **[Angular Elements API](https://v17.angular.io/api/elements)** — справочная информация по API, в частности, описание функций `createCustomElement()` и интерфейсов `NgElement` и `WithProperties`, которые важны для типизации.

### React

Документация React и практические руководства описывают как использовать Web Components внутри React-приложений.

- **[Web Components – React](https://ru.react.js.org/docs/web-components.html)** — официальное руководство React по использованию Web Components. В нем рассматривается работа с атрибутами (обратите внимание на `class` вместо `className`) и доступ к императивному API компонентов через `ref`.
- **[Pluralsight: Web Components Framework Integration](https://www.pluralsight.com/labs/codeLabs/guided-web-components-framework-integration)** — практический лабораторный материал, в котором показано: как передавать в Web Component строки через атрибуты, сложные объекты через сеттеры (используя `ref`), а также как принимать данные обратно через пользовательские события.

### Vue

Документация и примеры проектов показывают, как интегрировать Web Components во Vue-приложения.

- **[UI5 Web Components Vue Sample](https://github.com/UI5/sample-webcomponents-vue)** — пример проекта на GitHub, демонстрирующий использование Web Components (библиотеки UI5) во Vue. Особое внимание уделено настройке `compilerOptions.isCustomElement` в конфигурации Vite, чтобы Vue корректно обрабатывал пользовательские элементы.
- **[Six Group Vue Guide](https://six-group.github.io/six-webcomponents/v5/guide/vue.html)** — руководство по использованию библиотеки Web Components во Vue, включая установку, использование компонентов и интеграцию с `v-model` для работы с формами.

### Svelte

В Svelte есть встроенная поддержка компиляции компонентов в пользовательские элементы.

- **[Svelte Custom Elements API](https://v4.svelte.dev/docs/custom-elements-api)** — ключевой раздел официальной документации Svelte. Описывает опцию компилятора `customElement: true` и директиву `<svelte:options customElement="my-element">`. Подробно рассматриваются: настройка свойств (`props`), работа с Shadow DOM, особенности жизненного цикла компонентов-оберток и важные ограничения.

### Lit

Lit — легкая библиотека от Google для создания Web Components.

- **[Lit.dev Documentation](https://lit.dev)** — главный сайт с полной документацией. Lit предоставляет компонентный базовый класс для создания быстрых и легковесных Web Components с реактивным состоянием и инкапсуляцией стилей.
- **Mozilla Firefox Source Docs: Lit Guide** — практический пример и аргументация использования Lit для разработки высокореактивных элементов с декларативными шаблонами.

### Stencil

Stencil — это компилятор, генерирующий Web Components и предоставляющий возможности фреймворков (JSX, TypeScript, асинхронный рендеринг).

- **[Stencil Official Site](https://stenciljs.com)** — содержит введение, описание основных возможностей. Stencil создает Web Components, которые работают с любым фреймворком, и предоставляет мощные инструменты для создания дизайн-систем и библиотек компонентов.

### Межфреймворковое взаимодействие

Общие принципы и инструменты, облегчающие работу с Web Components в разных фреймворках.

- **Пакет `@lit/react`** — официальный пакет из экосистемы Lit, предоставляющий React-обертку для Web Components, что упрощает их использование.
- **Практики из Pluralsight** — та же лабораторная работа охватывает ключевые паттерны взаимодействия: передачу сложных объектов через свойства (сеттеры) и организацию двусторонней связи через пользовательские события с правильной очисткой слушателей в хуках `useEffect` для предотвращения утечек памяти.
- **Stencil Output Targets** — Stencil позволяет генерировать "нативные" обертки для React, Vue, Angular и других фреймворков, что делает интеграцию максимально бесшовной.

Эти источники предоставляют как теоретическую базу, так и практические примеры для каждой из рассматриваемых в главе тем.
