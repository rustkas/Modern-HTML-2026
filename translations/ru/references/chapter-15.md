Ниже приведен список ссылок на разделы спецификаций и справочные материалы для **Главы 15. Declarative Shadow DOM (DSD)**.

### Почему появился и основные концепции (SSR, Производительность)
Declarative Shadow DOM был разработан для того, чтобы позволить использовать преимущества инкапсуляции Shadow DOM в приложениях с серверным рендерингом без обязательной зависимости от JavaScript.

*   **MDN: Using shadow DOM — Declaratively with HTML** — объяснение того, почему для серверного рендеринга (SSR) декларативный подход обеспечивает лучшую производительность и пользовательский опыт по сравнению с императивным JS-подходом.
*   **HTML Standard: Section 4.12.3 The `template` element** — техническое описание элемента `<template>` как основы для создания фрагментов HTML, которые могут быть клонированы или использованы для создания теневых корней.
*   **MDN: Web Components — HTML templates** — введение в использование `<template>` и `<slot>` как базы для структуры кастомных элементов.

### Техническая реализация (Shadow Root и атрибуты)
Ключевым механизмом DSD является использование специальных атрибутов у тега `<template>`, которые браузер распознает во время парсинга HTML.

*   **HTML Standard: Атрибут `shadowrootmode`** — подробное описание перечисляемого атрибута, который активирует потоковую передачу декларативных теневых корней (состояния `open` и `closed`).
*   **HTML Standard: Атрибуты управления теневым корнем** — спецификации дополнительных свойств:
    *   `shadowrootdelegatesfocus` (делегирование фокуса).
    *   `shadowrootclonable` (возможность клонирования).
    *   `shadowrootserializable` (поддержка сериализации).
*   **DOM Standard: Section 4.8 Interface `ShadowRoot`** — программный интерфейс теневого корня, включая его свойства `mode`, `clonable` и `serializable`.

### SEO и гидратация
Хотя в спецификациях термин «SEO» встречается редко, механизмы DSD напрямую влияют на доступность контента для поисковых роботов и скорость «оживления» интерфейса.

*   **HTML Standard: Section 4.12.3 (Streaming declarative shadow roots)** — упоминание того, что DSD поддерживает потоковую передачу данных, что позволяет браузеру отрисовывать содержимое немедленно при парсинге.
*   **MDN: Using shadow DOM — Encapsulation from JavaScript** — демонстрация того, как элементы внутри Shadow DOM остаются скрытыми от обычных методов навигации по DOM (например, `querySelectorAll`), но доступны браузеру для рендеринга.
*   **HTML Standard: Section 3.1.1 (Allow declarative shadow roots)** — концепция документа, позволяющая или запрещающая использование декларативных теневых корней (булево свойство `allow declarative shadow roots`).

### Практические сценарии и совместимость
*   **MDN: Browser compatibility (shadowrootmode)** — таблица поддержки атрибута `shadowrootmode` и связанных технологий в современных браузерах.
*   **HTML Standard: Section 4.13.1.6 Upgrading elements after their creation** — описание процесса «апгрейда» (upgrades), когда кастомные элементы оживают (гидратируются) после загрузки скриптов, сохраняя при этом уже отрисованную через DSD структуру.

Использование этих источников позволяет полностью раскрыть тему перехода от чисто клиентской инкапсуляции к гибридным SSR-моделям, обеспечивающим мгновенную отрисовку контента.
